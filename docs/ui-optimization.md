# DustNote UI 优化方案（2026-09-25）

> 基线：`v2.5.45`。证据来源：`screenshots/` 实测截图逐张核对 + `web/src/index.css` / `web/src/lib/theme.ts` /
> `web/tailwind.config.js` 的 token 层扫描 + 全仓图标用字统计。
> 2026-09-25 二次修订：四条方向性决定已与高保真原型逐屏确认，见 §2；§3 起的阶段表已按定稿同步。`
> 结论先行：**问题不在审美，在地基。** 图标靠 emoji、颜色靠 7 个变量、层级靠一层渐变 ——
> 这种结构下任何局部美化都会在下一处露馅，这正是"改了很多版还是不满意"的机制原因。

---

## 1. 七条根因（每条都有可复核的证据）

### U-1 图标系统 = emoji（头号问题）

全仓统计（`web/src` 的 components / screens / lib / App.tsx，排除测试）：

| 指标             | 数值                                                                               |
| ---------------- | ---------------------------------------------------------------------------------- |
| 不同 emoji 字形  | **66 种**                                                                          |
| emoji 出现次数   | **274 次**                                                                         |
| 另混用的文本符号 | **110 次**（`✓ ✕ → ⌘ ↩` 等）                                                       |
| 高频 Top         | ✅×48 🗑️×14 🔗×11 📋×9 📌×9 📁×9 📝×8 ⭐×8 📦×7 📥×7 ⚠️×6 📱×5 🔒×5 🔍×5 🔄×5 🔐×5 |

小程序与安卓同样依赖 emoji（`miniprogram/src/pages/index/index.tsx` 11 处 / 8 种，
`mobile/src/screens/NotesListScreen.tsx` 11 处 / 6 种）。

**为什么它决定了"高级感"：**

- emoji 是**彩色位图字体**，不吃 `currentColor` → 无法跟随主题与明暗。`screenshots/dark-01-home.png`
  里顶栏 🔒 的橙色是整屏最亮的东西，而它只是个"锁屏"次级动作。
- 四端渲染三套 emoji 字体（Windows Segoe UI Emoji / 微信 / RN），**同一份代码四种观感**，
  尺寸与基线完全不可控。
- 与 `B` `I` `</>` `✓` `✕` 这类文本符号混排（见 `light-04-editor.png` 工具栏），等于同时用两套图标语言。
- 屏幕阅读器读 emoji 的结果是"锁"或"未知"，可访问性上是负分（A11Y 审计一直在修对比度，但图标本身没解）。

### U-2 全仓只有 14 个 token，没有层级 / 语义色 / 圆角尺度

实测全仓 token 面只有 **14 种**：7 个基础色（`--mn-bg` `--mn-fg` `--mn-fg-muted` `--mn-border`
`--mn-card` `--mn-accent` `--mn-accent-soft`）+ `--mn-font` + `--mn-line-height` + 5 个玻璃层
（`--mn-glass-surface` / `-surface-bg` / `-border` / `-button` / `-aurora`）。7 主题 × 2 模式 × 7 基础色
= **98 个手写值**（`web/src/lib/theme.ts`），而 `web/src/index.css` 的 `[data-mode='dark']` 只覆盖其中 5 个。

**缺的正是"层级"与"语义"两层**：没有 `surface-0/1/2/3` 层级、没有 `overlay`/`scrim`、没有 `shadow` 档位、
也没有 `success` / `warning` / `danger` / `info` 语义色，更没有 `radius` / `space` / `type` 尺度（圆角与间距全靠各组件自己写 `rounded-2xl p-6` 这类字面量）。
后果直接体现在截图上：

- 暗色模式 = "给极光渐变蒙一层灰"，正文与背景对比不足（`dark-01-home.png` 中央文案几乎看不见）。
- 小程序暗色出现**卡片双层描边**（`mp2-dark-home.png`：卡片外圈一条亮蓝、内部又一条），
  因为"边框"只有一个变量可用，谁都需要它就都用。
- 同一屏里搜索框、筛选 chip、文件夹 chip、tab、卡片是 **5 种不同容器语言**（边框宽度/圆角/透明度各不一致）。

### U-3 Tailwind 类被"影子类"劫持，类名在骗人

`web/tailwind.config.js` 里 `mint.*` 是一整套**硬编码绿色**（`#22c55e` 等），
而 `web/src/index.css` 的"Tailwind 颜色变量桥接"段（约 47–66 行）又手写了：

```css
.bg-mint-600 {
  background-color: rgb(var(--mn-accent));
}
.text-mint-300 {
  color: rgb(var(--mn-accent));
} /* ← 名字是 300，值是当前主题 accent */
.bg-mint-900\/30 {
  background-color: rgb(var(--mn-accent) / 0.15);
}
.hover\:bg-mint-700:hover {
  background-color: rgb(var(--mn-accent) / 0.85);
}
```

于是：写 `text-mint-300` 实际拿到"当前主题强调色"；同一类名在不同特异性下可能被 Tailwind 原版绿色接管；
改色结果取决于声明顺序。**这是"越改越不满意"的直接机制** —— 你无法预测一次改动的影响面，
只能靠"再叠一层覆盖"，覆盖层数一多，界面就进入不可维护状态。

### U-4 一个 `--mn-accent` 身兼六职

按钮底色、链接色、`blockquote` 左边条、`<mark>` 搜索高亮背景、`:focus-visible` 描边、选中态边框
——全是同一个变量（见 `index.css` 的 `.prose a` / `.prose blockquote` / `mark` / `:focus-visible`）。
结果：整屏"一片同色"，没有主次，焦点态与选中态与品牌态无法区分。

### U-5 没有排版尺度，也没有阅读宽度约束

- 字号零散硬编码：`.prose h1 { 1.875rem }`、`h2 { 1.5rem }`、`h3 { 1.25rem }`，与 UI 侧字号无共同比例。
- `--mn-line-height` 只有一个值；"密度（舒适/标准/紧凑）"只改行高，**不改字号与间距** ——
  所以切密度几乎没有感知差异，功能显得"假的"。
- 正文与标题**没有 `max-width`**：`web/src/components/Editor.tsx:775` 显式写了 `prose prose-sm max-w-none`
  （把 Tailwind typography 的阅读宽度主动关掉），于是 `light-04-editor.png` 里标题与正文横跨整屏（≈1400px），
  长文行长会远超 90 字符。排版高级感最先死在这里。

### U-6 操作无分组、无主次

`light-04-editor.png` 的编辑器工具栏从左到右：4 个模式 tab（每个还各带一个 emoji）→
`B I 🔗 • " </>` → `✅ 已加密保存` → `📌 ⭐  🔗  📋  🎤 `（**右侧 11 个平铺图标，无分组、无文字、
其中两个视觉上高度相似**）。顶栏另有 4 个无标签 emoji 按钮。
状态（已加密保存）与动作混排、危险动作（删除）与常用动作同权重、次级动作（导出）挤占主区。

### U-7 空状态与响应式脱节 + 端间漂移

- `web-mobile.png`：手机宽度下侧栏已折叠成汉堡，主区仍写"**选择左侧笔记开始阅读**" —— 指向不存在的 UI。
- 整个桌面主区在"未选中笔记"时是 100% 空白 + 一个小图标（`web-desktop-light.png`），
  没有最近编辑、没有概览、没有引导 —— 首屏信息密度接近 0。
- 设置弹窗（`light-05-settings.png`）：7 个主题卡在 3 列网格里**孤悬一行**；主题用 🌿🌫️🌲☕🌸◽🫧 表达，
  但 emoji 无法传达配色，用户只能靠猜；选中态只有 1px 蓝边 + 极浅底，对比不足。
- 根因是结构性的：`ARCH-R01`（token 单一源）**只做完了 web**，mobile / 小程序仍各写一份内联样式
  （见 `docs/audit-fixes-2026-09-21.md` 的"ARCH-R01（web 端已完成）"），所以四端必然越改越不一致。

## 2. 定稿决策（2026-09-25 原型逐屏确认 · 2026-09-26 实现期补一行首启口径）

| 决策 | 结论                                                           | 说明                                                                     |
| ---- | -------------------------------------------------------------- | ------------------------------------------------------------------------ |
| 主色 | 蓝 `#2563EB`（暗色 `#6FA4FF`）                                 | 主题卡默认选中「雾霭蓝调」；其余 6 套皮肤保留，由 seed 生成              |
| 玻璃 | **保留，默认开启**，设置里可关                                 | 收敛为三档材质 + 一条硬约束（§2.2）                                      |
| 首屏 | 未选中笔记 = **概览态**（统计 + 最近编辑 + 快捷入口 + 快捷键） | 替代原来的整屏空白（U-7）                                                |
| 布局 | **两栏：导航轨（树常驻）+ 舞台三态**                           | 列表与正文合并，用状态切换代替第三列（§2.1）                             |
| 首启 | 全新空间自动创建并打开欢迎笔记 —— **保留**                     | 概览仍是「未选中笔记」的落点；首启落正文对新用户更有引导性（09-26 确认） |

### 2.1 布局：导航轨 + 舞台三态

**导航轨 `216px`** —— 视图 / 文件夹（含二级、箭头折叠）/ 标签 chips 三段常驻可滚动。
**无背景卡、无边框、无容器**，只有行 + 缩进 + hover 底色：树要常驻，但别占地方、别抢注意力。

- 行高 `28px`（原 32px）；子级缩进 `+19px`；分组标题 `11px / 650 / 字距 .07em` 的轻标签，不做卡片标题
- 计数右对齐 `tabular-nums`；**hover 该行时计数让位给行内操作**，一行不同时塞三样
- 分组标题右侧的 `+`（新建文件夹 / 新建标签）只在该分组 hover 时出现
- 选中行 = `accent-soft` 底 + accent 文字 + 600 字重；**不加左侧竖条**（列表选中已有竖条，两处都用会打架）
- 标签超过 8 个折叠为「+N 更多」，不整段消失；底部一行常驻同步状态

**舞台 `1224px`（1440 屏）** —— 三态共用同一列，切换只换内容不换骨架：

| 态   | 内容与宽度约束                                                                                                                       |
| ---- | ------------------------------------------------------------------------------------------------------------------------------------ |
| 概览 | 统计卡 + 最近编辑 + 快捷操作 + 快捷键提示                                                                                            |
| 列表 | 行宽 `88ch`：摘要两行 + 字数 + 标签 + 同步点；hover 出行内操作                                                                       |
| 详情 | `stagehead`（导航：`← 全部笔记` · 路径面包屑 · `‹ 3/11 ›` · `Esc` 提示）+ `toolbar`（工具：模式分段 · 格式 · 状态 · 动作）+ 阅读纸张 |
| 搜索 | 命中分组（标题命中 / 正文命中）+ 两行摘要 + `<mark>` 高亮                                                                            |

- **状态机**：概览 →（点列表 / `Ctrl N`）→ 列表 →（打开笔记）→ 详情；`Esc` 逐级回退，`Ctrl K` 随时进搜索，`←/→` 或 `‹ ›` 在结果集内翻篇
- **阅读纸张**：`68ch + 88px` 内边距，落在 `glass-2` 上（圆角 + 描边 + `shadow-sm`）；分屏态放宽为 `2 × 46ch`
- **断点**：≥1280 全轨 / 1024–1279 收成 `56px` 图标轨 + tooltip / <1024 导航抽屉 + 舞台退化为逐屏推进
- **合并的代价与对策**：看不到"列表 + 正文"同屏 → 结果集内翻篇 + 概览常驻最近编辑；返回列表保留滚动位置与选中行（不重新拉数据）；拖拽移动笔记改为"拖到导航轨高亮行投放"

**2.8 + 阶段 2.1 已落地补充（2026-09-26）**

- 导航轨宽度按设计取 **216px**；目的地四按钮（概览 / 全部笔记 / 收藏 / 回收站）在这个宽度下横排会互相压字，
  改为 **2×2 网格 + 图标与文字同行**。
- 详情态两行分工已照做：`StageHead`（导航：`← 目的地` · 文件夹链面包屑 · `‹ 3/11 ›` · `Esc` 提示）
  与工具栏（工具）分开，工具栏三段式 = 左 segmented（选中实底 `bg-accent-strong`）·
  中格式工具（**只在编辑 / 分屏出现**，`B`/`I`/`🔗`/`❝`/`</>` 全部换真图标）·
  右 = 状态（`shield-check` + 已加密保存，12px 次要色）+ 4 个常驻动作 + `⋯` 溢出（历史 / 存为模板 /
  剪贴板插入 / 删除标 danger）。
- 阅读纸张：`.paper-sheet` = `68ch + 88px` 内边距落在 `glass-2` 上；分屏 `.paper-sheet--split`
  放宽为 `2 × 46ch` 并把内边距对半（否则两栏之间会空出 176px）；<1024 铺满、内边距收到 20px。
  正文区自己去掉了横向 `p-6` —— 纸张已经给了边距，再叠一层会把一行挤到 40ch。

### 2.2 玻璃：三档材质 + 一条硬约束（已落地）

| 档                | 浅色                                             | 暗色                | 用途                               |
| ----------------- | ------------------------------------------------ | ------------------- | ---------------------------------- |
| `--mn-glass-1`    | `255 255 255 / .74`                              | `card / .60`        | 顶栏、导航轨（`.glass-1`）         |
| `--mn-glass-2`    | `255 255 255 / .88`                              | `card / .80`        | 卡片、弹窗、阅读纸张、舞台头部     |
| `--mn-glass-line` | `fg / .09`                                       | `255 255 255 / .10` | 玻璃面板之间的分隔（替代实心灰线） |
| `--mn-aurora`     | `0 / .5 / 1 / 1.4` 四档乘数，**默认 .5（柔和）** | 同                  | 光斑只画在 `body::before` 一层     |

**落地要点（与当初设计的差别，都值得记一笔）**

1. **材质与主题解耦**：改造前玻璃是 `liquid-glass` 这个主题的专利（`html[data-theme='liquid-glass']` 下 160 行 CSS 把 `.bg-surface-card`、`input`、滚动条全改成半透明）。
   现在开关是 `html[data-effect='glass'|'flat']`，三档由 `.glass-1` / `.glass-2` **按角色挂**，
   弹窗按 `role="dialog"` 统一吃 `glass-2`（新增弹窗不必记得挂类名）。
   那 160 行整体从 `web/src/index.css` 搬进 `shared/styles/tokens.css` —— 桌面端复用 web 组件，
   两边必须吃同一份材质定义（U-3 的成因就是"各写一套"）。
2. **极光默认从"吃满"降到 .5**：截图里概览与列表像泡在蓝雾里，就是这一档造成的；
   它同时是上一版 `contrast-report` 里 **105 处玻璃最坏情况**的主要来源。现在实测 **0 处**。
3. **引擎必须把玻璃算进承载面**：`deriveTokens()` 的 `surfaces` 原先只有 `bg / card / surface-2 / surface-3`，
   于是"实心卡上 AA、放到玻璃面板上掉档"没人管（实测暗色设置弹窗的 `退出登录` 只有 3.04:1）。
   现在额外压入两档玻璃的最差情况（透出的一半全是 accent），文字与状态色一次算清，七套主题同时受益。
4. **两条退路**：`prefers-reduced-transparency: reduce` 与"引擎不支持 `backdrop-filter`"时，
   极光停掉、面板退回实色 —— 否则文字就是直接压在渐变上，违反下面那条硬约束。
5. **状态色此前是哑的**：色表把状态色嵌在 `state` 下（类名应为 `text-state-danger`），
   而全仓写的是 `text-danger` / `bg-danger-soft` —— Tailwind 生成不出规则，11 处危险/警告色样式一直是空的。
   已拉平成扁平名（`state-*` 零使用，直接放弃），并顺手把 121 处硬编码 `text-red-600` 一类换成语义令牌。

**硬约束（不变）**：任何文字不得直接压在 aurora 上；`glass-2` 之上的正文在浅色与暗色下都必须实测 ≥ 4.5:1。
`[data-effect]` 只切材质，布局 / 间距 / 字号零位移；关闭玻璃后所有面板回实色 `surface`。

**度量口径的两处修正**（数字变好之前，先确认量具没瞎）：
极光从 `body` 的 `background` 挪到 `body::before` 后，审计器沿 `parentElement` 链走，**看不见伪元素**，
`glassWorstCase` 会假性归零 —— 已在 `e2e/a11y-contrast.ts` 里显式读取伪元素的渐变并计入最坏情况；
同时修掉 `out.unresolved += 1` 这个笔误（对象上没这个字段，样本数永远报 0）。
修正后本轮实测：**148 个文字样本按极光最坏情况判定，失败 0**。

### 2.4 1.1 与 2.8 的落地机制（同日追加）

**B 类（i18n 串里内嵌 emoji）的拆法** —— `components/Icon.tsx` 里的 `LABEL_ICON`
（i18n key → 图标名）+ `<IconText k label />`：词典只留文字，图标由这张表提供。
已迁移编辑器视图切换与侧栏批量操作（zh + en 共 18 条）。
剩余 **310 条**（web 118 / mobile 46+46 / 小程序 51+49）用**棘轮**管理：
`scripts/check-i18n.mjs` 第 5 节把当前数量写死成上限，只许减少不许增加 ——

该规则上线当轮就抓到实现者自己写的未定义 key（`common.untitled`）。

**测试工具的连带修复**：`web/src/test/render.tsx` 的 `getByText` 在没有纯文本叶子时按文档序
返回匹配，按钮里一放 `<svg>` 就退到外层容器、点击静默失效。改为取"最内层匹配"
（与 @testing-library 一致）。**不修这一条，后续每次图标迁移都会重踩。**

**2.8 舞台三态的第一块：概览态**。`web/src/components/Overview.tsx` 替代原先"整屏空白 + 一个 📝"：
统计（只数未删除）+ 最近编辑 5 条（倒序、排除回收站、点击打开）+ 快捷操作 + 快捷键提示。

覆盖不到"未选中"这一态，所以必须有单测。

### 2.5 舞台状态机（2.8 的契约层）

「该显示哪一态」以前散在 `Sidebar` 与 `Editor` 的若干 `if (!note) return …` 里，
改布局只能靠肉眼回归。现在收敛成纯函数 `web/src/lib/stage.ts`：

- `resolveStage({ destination, searchQuery, selectedNoteId })` → `detail > search > list > overview`
  - **`destination` 取代了原先的 `hasScope` 猜测**：`viewMode` 增加 `'overview'` 并成为默认值。
    之前「冷启动」与「点了全部笔记」在 store 里是同一个状态，列表态因此没有稳定入口 ——
    缺的就是一个 bit 的事实，加判据也猜不出来，只能补进状态里。
  - **`detail` 压在 `search` 之上**（与直觉相反，所以写明）：两栏合并后点开一条命中必须看到正文，
    否则结果列表会把它弹回去。配套约定：`setSearchQuery` 在查询变非空时清掉选中笔记 ——
    「开始搜索 = 离开正文」「点开命中 = 回到正文且查询词留在框里等 Esc」。
- `nextOnEscape(input)` → `close-detail | clear-search | clear-scope | stay`；
  `scopeBack(input)` 决定 clear-scope 的去向（子范围 → 全部笔记，全部笔记 → 概览）。
  **根列表与概览都是终点**：在「全部笔记」里按 Esc 把人扔到统计页，只会让人觉得点坏了。
- `stepInSet(ids, current, delta)` → 结果集内翻篇，**到边界停住而不是循环**。
- `stagePosition(order, id)` → 舞台头部的 ‹ 3/11 ›；不在结果集里（从概览的最近编辑点进来）就不显示。
- `stageHasBack(mode)` → 只有详情需要返回。

配套三件事：

1. `searchQuery` 从 `Sidebar` 的局部 state 提到 store（`data-slice`）—— 状态机要读它，就必须有唯一来源。
2. `stageOrder`（列表态解析出的有序 id）也提到 store：详情态会卸载 `NoteList`，而「从哪一列结果进来」
   必须活过这次卸载，否则翻篇没有依据。唯一写它的是 `lib/note-scope.ts`。
3. 舞台与 `Editor` 不再各自渲染 `<main id="main-content">`：`main` 归 `App.tsx` 唯一，
   「跳到主内容」的落点才确定（原先是嵌套 main + 重复 id）。

**接线范围（2.8 已收口）**：`detail → StageHead + Editor`、`list / search → NoteList`、
`overview → Overview`。导航轨的目的地就是状态机输入；`←/→` 与 ‹ › 读同一份结果集。
`e2e/visual-baseline.spec.ts` 的「舞台三态」用例把这条链固化成回归基线：
概览首屏 → 列表行数 → 头部位置 1/N → ‹ → 与方向键翻到 N/N 且停住 → Esc 逐级回退 → 概览。

## 3. 方案：三阶段，**顺序不可换**

## 4. 验收口径（可量化，避免"我觉得好看了"）

| ---------- | ------------------------------------------------------------------ | ------------------------------------------------------------------------------------ |
| 图标       | 功能图标里的 emoji 数量                                            | **0**（正文内容里的 emoji 不计）                                                     |

| 回归保护   | 视觉基线                                                           | 每端 8 页截图基线（复用现有 `shoot.mjs`），CI 比对差异 < 阈值                        |

## 5. 风险与规避
