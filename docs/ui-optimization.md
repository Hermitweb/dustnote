# DustNote UI 优化方案（2026-09-25）

> 基线：`v2.5.45`。证据来源：`screenshots/` 实测截图逐张核对 + `web/src/index.css` / `web/src/lib/theme.ts` /
> `web/tailwind.config.js` 的 token 层扫描 + 全仓图标用字统计。
> 结论先行：**问题不在审美，在地基。** 图标靠 emoji、颜色靠 7 个变量、层级靠一层渐变 ——
> 这种结构下任何局部美化都会在下一处露馅，这正是"改了很多版还是不满意"的机制原因。

---

## 1. 七条根因（每条都有可复核的证据）

### U-1 图标系统 = emoji（头号问题）

全仓统计（`web/src` 的 components / screens / lib / App.tsx，排除测试）：

| 指标             | 数值                                                                               |
| ---------------- | ---------------------------------------------------------------------------------- |
| 不同 emoji 字形  | **66 种**                                                                          |
| emoji 出现次数   | **274 次**                                                                         |
| 另混用的文本符号 | **110 次**（`✓ ✕ → ⌘ ↩` 等）                                                       |
| 高频 Top         | ✅×48 🗑️×14 🔗×11 📋×9 📌×9 📁×9 📝×8 ⭐×8 📦×7 📥×7 ⚠️×6 📱×5 🔒×5 🔍×5 🔄×5 🔐×5 |

小程序与安卓同样依赖 emoji（`miniprogram/src/pages/index/index.tsx` 11 处 / 8 种，
`mobile/src/screens/NotesListScreen.tsx` 11 处 / 6 种）。

**为什么它决定了"高级感"：**

- emoji 是**彩色位图字体**，不吃 `currentColor` → 无法跟随主题与明暗。`screenshots/dark-01-home.png`
  里顶栏 🔒 的橙色是整屏最亮的东西，而它只是个"锁屏"次级动作。
- 四端渲染三套 emoji 字体（Windows Segoe UI Emoji / 微信 / RN），**同一份代码四种观感**，
  尺寸与基线完全不可控。
- 与 `B` `I` `</>` `✓` `✕` 这类文本符号混排（见 `light-04-editor.png` 工具栏），等于同时用两套图标语言。
- 屏幕阅读器读 emoji 的结果是"锁"或"未知"，可访问性上是负分（A11Y 审计一直在修对比度，但图标本身没解）。

### U-2 全仓只有 14 个 token，没有层级 / 语义色 / 圆角尺度

实测全仓 token 面只有 **14 种**：7 个基础色（`--mn-bg` `--mn-fg` `--mn-fg-muted` `--mn-border`
`--mn-card` `--mn-accent` `--mn-accent-soft`）+ `--mn-font` + `--mn-line-height` + 5 个玻璃层
（`--mn-glass-surface` / `-surface-bg` / `-border` / `-button` / `-aurora`）。7 主题 × 2 模式 × 7 基础色
= **98 个手写值**（`web/src/lib/theme.ts`），而 `web/src/index.css` 的 `[data-mode='dark']` 只覆盖其中 5 个。

**缺的正是"层级"与"语义"两层**：没有 `surface-0/1/2/3` 层级、没有 `overlay`/`scrim`、没有 `shadow` 档位、
也没有 `success` / `warning` / `danger` / `info` 语义色，更没有 `radius` / `space` / `type` 尺度（圆角与间距全靠各组件自己写 `rounded-2xl p-6` 这类字面量）。
后果直接体现在截图上：

- 暗色模式 = "给极光渐变蒙一层灰"，正文与背景对比不足（`dark-01-home.png` 中央文案几乎看不见）。
- 小程序暗色出现**卡片双层描边**（`mp2-dark-home.png`：卡片外圈一条亮蓝、内部又一条），
  因为"边框"只有一个变量可用，谁都需要它就都用。
- 同一屏里搜索框、筛选 chip、文件夹 chip、tab、卡片是 **5 种不同容器语言**（边框宽度/圆角/透明度各不一致）。

### U-3 Tailwind 类被"影子类"劫持，类名在骗人

`web/tailwind.config.js` 里 `mint.*` 是一整套**硬编码绿色**（`#22c55e` 等），
而 `web/src/index.css` 的"Tailwind 颜色变量桥接"段（约 47–66 行）又手写了：

```css
.bg-mint-600 {
  background-color: rgb(var(--mn-accent));
}
.text-mint-300 {
  color: rgb(var(--mn-accent));
} /* ← 名字是 300，值是当前主题 accent */
.bg-mint-900\/30 {
  background-color: rgb(var(--mn-accent) / 0.15);
}
.hover\:bg-mint-700:hover {
  background-color: rgb(var(--mn-accent) / 0.85);
}
```

于是：写 `text-mint-300` 实际拿到"当前主题强调色"；同一类名在不同特异性下可能被 Tailwind 原版绿色接管；
改色结果取决于声明顺序。**这是"越改越不满意"的直接机制** —— 你无法预测一次改动的影响面，
只能靠"再叠一层覆盖"，覆盖层数一多，界面就进入不可维护状态。

### U-4 一个 `--mn-accent` 身兼六职

按钮底色、链接色、`blockquote` 左边条、`<mark>` 搜索高亮背景、`:focus-visible` 描边、选中态边框
——全是同一个变量（见 `index.css` 的 `.prose a` / `.prose blockquote` / `mark` / `:focus-visible`）。
结果：整屏"一片同色"，没有主次，焦点态与选中态与品牌态无法区分。

### U-5 没有排版尺度，也没有阅读宽度约束

- 字号零散硬编码：`.prose h1 { 1.875rem }`、`h2 { 1.5rem }`、`h3 { 1.25rem }`，与 UI 侧字号无共同比例。
- `--mn-line-height` 只有一个值；"密度（舒适/标准/紧凑）"只改行高，**不改字号与间距** ——
  所以切密度几乎没有感知差异，功能显得"假的"。
- 正文与标题**没有 `max-width`**：`web/src/components/Editor.tsx:775` 显式写了 `prose prose-sm max-w-none`
  （把 Tailwind typography 的阅读宽度主动关掉），于是 `light-04-editor.png` 里标题与正文横跨整屏（≈1400px），
  长文行长会远超 90 字符。排版高级感最先死在这里。

### U-6 操作无分组、无主次

`light-04-editor.png` 的编辑器工具栏从左到右：4 个模式 tab（每个还各带一个 emoji）→
`B I 🔗 • " </>` → `✅ 已加密保存` → `📌 ⭐  🔗  📋  🎤 `（**右侧 11 个平铺图标，无分组、无文字、
其中两个视觉上高度相似**）。顶栏另有 4 个无标签 emoji 按钮。
状态（已加密保存）与动作混排、危险动作（删除）与常用动作同权重、次级动作（导出）挤占主区。

### U-7 空状态与响应式脱节 + 端间漂移

- `web-mobile.png`：手机宽度下侧栏已折叠成汉堡，主区仍写"**选择左侧笔记开始阅读**" —— 指向不存在的 UI。
- 整个桌面主区在"未选中笔记"时是 100% 空白 + 一个小图标（`web-desktop-light.png`），
  没有最近编辑、没有概览、没有引导 —— 首屏信息密度接近 0。
- 设置弹窗（`light-05-settings.png`）：7 个主题卡在 3 列网格里**孤悬一行**；主题用 🌿🌫️🌲☕🌸◽🫧 表达，
  但 emoji 无法传达配色，用户只能靠猜；选中态只有 1px 蓝边 + 极浅底，对比不足。
- 根因是结构性的：`ARCH-R01`（token 单一源）**只做完了 web**，mobile / 小程序仍各写一份内联样式
  （见 `docs/audit-fixes-2026-09-21.md` 的"ARCH-R01（web 端已完成）"），所以四端必然越改越不一致。

## 2. 方案：三阶段，**顺序不可换**

> 先给"可改性"（阶段 1），再给"秩序"（阶段 2），最后才给"质感"（阶段 3）。
> 反过来做（先调渐变、先换配色）只会增加覆盖层数，回到 U-3 的困境。

### 阶段 1 · 地基（3–5 天；视觉几乎不变，但从此可维护）

| #   | 动作                                                                                                                                                                                                                                                                                                                      | 落点 / 产出                                                                                                                                                                                                                                                                                                                                                                                                                        |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1.1 | **图标系统落地**：`lucide-react`（web / desktop）、`react-native-svg` + 同一份 SVG（mobile）、iconfont 或内联 SVG（小程序）。统一 `<Icon name size={16\|20\|24} strokeWidth={1.75} />`，颜色一律 `currentColor`。为 66 种 emoji 建映射表并全量替换（先做 Top 20 高频，覆盖 ~80% 出现次数）                                | 新增 `web/src/components/Icon.tsx` + `shared` 或新包里的 `icons.ts` 名称清单；映射示例：📁→`Folder` 📌→`Pin` ⭐→`Star` 🗑→`Trash2` 🔗→`Link` 📋→`ClipboardList` 🔍→`Search` ✅→`ShieldCheck` 🔐→`LockKeyhole` 🔓→`LockOpen` 🎤→`Mic` ⚡→`Zap` ✨→`Sparkles` ☀️→`Sun` 🌙→`Moon` 🌓→`Monitor` ⚠️→`AlertTriangle` ✕→`X` ↩️→`Undo2` 📄→`FileText` 📝→`NotebookPen` 📦→`Archive` 📥→`Download` 🔄→`RefreshCw` ⚙️→`Settings` 🛠️→`Wrench` |
| 1.2 | **token 从 7 → 约 40 个语义层**：`surface-0/1/2/3`、`text-primary/secondary/tertiary/inverse/on-accent`、`accent/accent-hover/accent-soft/accent-contrast`、`success/warning/danger/info`、`overlay`/`scrim`、`focus-ring`、`shadow-sm/md/lg`、`radius-sm/md/lg/xl/full`、`space-1..12`（4px 基准）、type scale（xs→4xl） | `web/src/index.css` 的 `:root` + `theme.ts`；小程序 `app.scss`、mobile `theme.ts` 由同一模块生成（同时结掉 `ARCH-R01`）                                                                                                                                                                                                                                                                                                            |
| 1.3 | **主题改成"生成"而不是"手写"**：每主题只提供 1 个 seed（品牌色 + 中性色相 + 明度曲线），用 OKLCH 色阶生成 7×2×40 个值。`theme.ts` 从 98 个手写值降到 7 个 seed + 生成器，且**对比度可保证**（暗色下自动提亮 accent 到 AA）                                                                                                | 新增 `shared/src/theme-engine.ts`（纯函数 + 单测）；四端消费                                                                                                                                                                                                                                                                                                                                                                       |
| 1.4 | **删影子类**：Tailwind 直接消费变量（`bg-surface-1`、`text-text-secondary`），从 `tailwind.config.js` 移除 `mint.*`，删除 `index.css` 的"桥接"段；加 stylelint 规则禁止组件内出现 `#hex` / `rgb()`（白名单例外）                                                                                                          | 影响面最大的一步，**必须在 1.2/1.3 之后**，并用阶段 3 的视觉回归兜底                                                                                                                                                                                                                                                                                                                                                               |
| 1.5 | **排版尺度 + 阅读宽度**：`--measure: 68ch` 应用于 `.prose` / 编辑器 / 标题；密度同时改字号与间距（紧凑 13/1.5、标准 14/1.65、舒适 15/1.75）；数字统一 `font-variant-numeric: tabular-nums`（时间戳、计数不再跳动）                                                                                                        |

### 阶段 2 · 秩序（1 周；视觉开始变化，但只改"排布与层级"，不改配色）

| #   | 动作                                                                                                                                                                                                                                                                                                                                                                                     |
| --- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 2.1 | **编辑器工具栏三段式**：左 = segmented control（编辑 / 分屏 / 预览 / 所见即所得，纯文字 + 图标，选中实底）；中 = 格式工具（仅"编辑/分屏"时出现，`B`/`I` 换成 `Bold`/`Italic` 真图标，代码用 `Code`）；右 = 状态（`ShieldCheck` + 「已加密保存」，12px 次要色，与动作分离）+ **4 个常驻动作**（Pin / Star / 移动文件夹 / 分享）+ `⋯` 溢出菜单收纳其余 7 个；删除按钮进溢出菜单并标 danger |
| 2.2 | **顶栏**：4 个无标签 emoji → 图标按钮 + `aria-label` + tooltip，按语义分组（管理工具 ｜ 分享 ｜ 设置 ｜ 锁屏）；**锁屏改为带文字的按钮**（关键动作不能只靠图标传达）                                                                                                                                                                                                                     |
| 2.3 | **容器语言收敛为 3 个组件**：`Panel`（`surface-1` + 1px border + `radius-md`，无阴影）、`Card`（`surface-2` + `shadow-sm`）、`Field`（输入/搜索）。选中态统一用"左侧 3px accent bar + `surface-2`"，而不是换底色 —— 解决小程序双层描边与 web 侧栏选中态弱的问题                                                                                                                          |
| 2.4 | **空状态四态化**：首次使用（引导新建 / 导入 / 连接服务器）、无搜索结果（给出改关键词建议）、当前文件夹为空、未选中笔记（桌面显示"最近编辑 5 条"，移动端文案改为"点右上角 + 新建"）。**文案必须随断点变**（修 U-7）                                                                                                                                                                       |
| 2.5 | **弹窗规范**：`scrim` = `rgba(0,0,0,.55)` + `backdrop-blur`；Dialog 用 `surface-2` + `shadow-lg` + `radius-xl`；标题 20/600；分组标签 12/600/tertiary；主题卡网格改为自动换行 + 上限 4 列（消除孤悬行）；选中态 = 2px accent 边框 + 右上 `Check` 徽标；`max-height: 72vh` + 内滚动                                                                                                       |
| 2.6 | **主题选择改成"真实配色预览"**：每卡显示 accent 圆点 + bg/card/文字 三条色带 + 名称（删掉 🌿🫧 这类无法传达配色的 emoji），并在卡片上直接体现明暗两态                                                                                                                                                                                                                                    |
| 2.7 | **小程序专项**：去掉卡片双层描边（bug 级）；两个 FAB（模板 + 新建）合并为 1 个主 FAB，模板降为工具条次级入口；时间戳格式与 web 对齐（`DOC-003` 同源问题）；tab「收藏 / 回收站」在暗色下的次要文字提到 AA                                                                                                                                                                                 |

### 阶段 3 · 质感（1–2 周；方向确认后再投）

| #   | 动作                                                                                                                                                                                                                                                |
| --- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 3.1 | **"玻璃"降级为效果开关**（`effect: flat \| glass`，默认 `flat`）：`backdrop-blur` 只用于顶栏与浮层，内容区回到实色 `surface`。现在整屏极光让文字对比度不可控，且在低端安卓/小程序上有明显掉帧成本                                                   |
| 3.2 | **暗色是"重设"不是"覆盖"**：`surface-0 ≈ oklch(17% .015 h)`，逐层 +4–5% L，层级靠亮度差而非彩色边；极光最多保留 1 个光斑且不透明度 ≤ 8%                                                                                                             |
| 3.3 | **动效 token**：120 / 180 / 240ms + `cubic-bezier(.2,0,0,1)`；列表进出、抽屉、弹窗、toast 统一时长与缓动；web 已具备 `prefers-reduced-motion`（`index.css:130`、`:182`），补齐 RN 动画层与**小程序设置开关**（weapp 不吃该媒体查询，即 `A11Y-R05`） |
| 3.4 | **三态一致**：hover / active / focus-visible 全部由 token 给值；focus 环在暗色下必须可见（当前 `--mn-accent` 在某些暗色主题上与背景同亮度）                                                                                                         |
| 3.5 | **微排版**：按钮高度 32/36/40 三档、图标按钮 28/32 两档、图标与文字固定 6px 间隙、卡片内边距只用 `space-3/4/5`、分割线只用一档                                                                                                                      |

## 3. 验收口径（可量化，避免"我觉得好看了"）

| 维度     | 指标                                                               | 门槛                                                                                 |
| -------- | ------------------------------------------------------------------ | ------------------------------------------------------------------------------------ |
| 图标     | 功能图标里的 emoji 数量                                            | **0**（正文内容里的 emoji 不计）                                                     |
| 一致性   | 组件内硬编码颜色（`#hex` / `rgb()`）                               | 0（stylelint 门禁 + 白名单）                                                         |
| 可访问性 | 文字对比度                                                         | 全部 ≥ AA 4.5:1（大字 ≥ 3:1），Playwright + axe 跑 8 页 × 明暗 × 抽 3 主题，报告归档 |
| 回归保护 | 视觉基线                                                           | 每端 8 页截图基线（复用现有 `shoot.mjs`），CI 比对差异 < 阈值                        |
| 密度感知 | 切换"舒适/标准/紧凑"后的可测差异                                   | 字号 + 行高 + 间距三者同时变化                                                       |
| 端间漂移 | 同一 token 模块驱动四端                                            | `ARCH-R01` 关闭                                                                      |
| 主观     | 改前 / 改后各 6 张截图做小样本 A/B（"哪个更像你愿意长期用的笔记"） | 记录选择率，作为是否继续投阶段 3 的依据                                              |

## 4. 风险与规避

| 风险                                            | 规避                                                                              |
| ----------------------------------------------- | --------------------------------------------------------------------------------- |
| 1.4 删影子类会一次性碰到大量组件类名 → 全站变色 | 先建视觉回归基线（第 3 节）再动；按页面分 4 个 commit，每个都能单独回滚           |
| 图标替换改变布局宽度（emoji 宽度不稳定）        | `Icon` 固定尺寸盒 + 先替换一个页面观察，再批量                                    |
| 小程序 iconfont/SVG 引入体积与审核              | 优先内联 SVG（微信支持 data URI），必要时子集化字体；先在 H5 产物验证             |
| 主题生成器改动历史账号的观感                    | 保持 7 个主题 ID 与默认项不变，只换内部实现；对老用户偏好零迁移                   |
| "玻璃"关掉后失去产品识别度                      | 保留为可选开关，默认 `flat`；把玻璃留给浮层/顶栏这一处，反而更突出                |
| 单人维护，UI 专项容易挤占功能与运维             | 严格按阶段投：阶段 1 完成前不动配色；每阶段末发一次 preview tag，不满意可停在原地 |

## 5. 与总体路线图的关系

本方案不是插入的第三条独立线，而是 `docs/roadmap.md` 里 **R2「结构债」的一部分提前**：
阶段 1.2 / 1.3 与审计项 `ARCH-R01`（token 单一源）是同一件事，做完同时关闭一项挂账；
阶段 3.3 关闭 `A11Y-R05`；阶段 2.7 的时间戳与文案关闭 `DOC-003` 在小程序端的复发；
第 3 节的 axe 门禁则让 `A11Y-R01/R02/R03` 不再反复。

建议排期：**R0（止血）之后立刻做阶段 1**，阶段 2 随 `v2.6.0`，阶段 3 视 A/B 结果决定是否进 `v2.7.0`。

## 6. 下一步（二选一，可直接开工）

- **A（推荐，风险最低）**：先出一份**高保真静态原型**（单 HTML/Tailwind：主页 + 编辑器 + 设置弹窗 + 暗色，
  采用新 token 与 lucide 图标方案），你在真实视觉上确认方向，再回来改代码。避免"改了四端才发现不喜欢"。
- **B**：直接落地**阶段 1**（theme-engine + Icon + 影子类清理 + 排版尺度），布局与配色不动，
  产出是一次"看不出变化但从此可改"的重构，附带视觉回归基线。
