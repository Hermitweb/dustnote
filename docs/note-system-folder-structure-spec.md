# 笔记系统｜目录列表结构 产品设计规范（正式版）

## 1\. 设计总纲

本系统目录结构采用**「扁平优先、浅嵌套、可控层级、容器隔离」**的设计范式。

核心设计哲学：**文件夹负责宏观分类，搜索/标签负责微观筛选，拒绝深度树形嵌套**。

目标体验：少折叠、少点击、高曝光、低归档成本，适配个人知识库长期迭代。

## 2\. 层级结构定义（核心架构）

### 2\.1 层级硬性约束（系统级规则）

- **最大层级深度：3层封顶**（Root → 一级文件夹 → 二级文件夹/笔记）

- **禁止四级及以上嵌套**，代码层面直接拦截

- **笔记文件为最终叶子节点**，文件下不允许挂载任何内容

- 一级文件夹**只做领域容器**，默认不直接存放笔记（可选放开兼容）

### 2\.2 标准结构模型（系统默认范式）

默认以「二级扁平」为主体，三级嵌套为弹性扩展：

```Plain Text
根目录
├─ 一级分类（大领域/大板块）
│  ├─ 笔记（平铺展示，主流形态）
│  └─ 二级子文件夹（按需使用，非常规）
└─ 一级分类
   └─ 笔记平铺
```

### 2\.3 结构形态说明

- **90% 日常场景：二级扁平结构**

  - 一级文件夹 → 直接平铺所有笔记

  - 优点：一览无余、无需频繁展开折叠、列表渲染简单

- **10% 复杂场景：三级浅嵌套**

  - 仅用于项目、系列教程、大批量同主题内容

  - 严格禁止泛滥使用，保证整体结构清爽

## 3\. 顶层分类设计语言（固定范式）

系统顶层永久遵循**「二元隔离原则」**，所有内容只归属两大顶层分支：

1. **业务/项目分支**：对外、任务、项目、特定场景资料

2. **个人/沉淀分支**：通用技术、学习积累、工具手册、个人资产

设计意图：**按「归属场景」切分，而非按「文件类型」切分**，符合人脑归档直觉。

## 4\. 文件夹与文件设计规则

### 4\.1 文件夹定位规则

- 文件夹 = **宏观语义容器**，不承担精细分类职责

- 不鼓励建立细碎、小众、窄维度文件夹

- 细分检索需求，全部交给：搜索、标签、筛选、过滤

### 4\.2 笔记文件定位规则

- 文件名自解释、高信息密度，依托列表平铺直接阅读意图

- 单文件单主题，避免大杂烩笔记

- 文件同级无排序优先级，默认按更新/创建时间排序即可

## 5\. 列表 UI 与交互设计规范

适配上述结构，定义系统专属列表交互风格：

- **扁平优先展示**：二级目录默认展开，减少用户点击成本

- **轻量化树结构**：去除多余缩进、多余层级线条，界面干净

- **文件高密度平铺**：支持单目录大量文件列表渲染，不卡顿、不折叠

- **层级拦截提示**：用户创建四级目录时，系统弹窗拦截并给出规范提示

## 6\. 本架构的核心设计取舍（产品底层逻辑）

### 6\.1 牺牲项

- 放弃极致精细化树形分类

- 放弃无限自由嵌套

### 6\.2 换取项

- 极低的用户归档思考成本

- 极高的内容曝光率，笔记不深埋、不吃灰

- 极简的前端结构、路由、路径解析逻辑

- 极强的长期迭代稳定性

## 7\. 与主流笔记系统的差异化优势

- 比 Notion 更克制：不允许无限嵌套，结构不乱

- 比 Obsidian 更规范：有层级约束，不会无限平铺臃肿

- 比传统文件夹系统更智能：分类靠结构 \+ 检索双能力，而非纯手动分层

## 8\. 最终一句话设计定义（可做系统 Slogan）

**以扁平平铺为默认，以浅嵌套为扩展，以顶层二元隔离为秩序，以检索体系承载细分分类。**
