### 0.2 体检发现的 6 个真实缺口（本路线图的主轴）

1. **线上拓扑与文档不一致**（实测）
   `docs/status.md` 与 README 全部指向 `http://154.217.234.125:8080/`，但外网探测结果：
   - `TCP 8080` → **不通**（同机 80/443 通，说明不是网络不可达）
   - `http://154.217.234.125/` → 200，但内容是**个人主页**（尘渊 · Hermitweb），不是 DustNote；该 vhost 的 `/api/*` → 404
   - `https://154.217.234.125/api/v1/health` → **200** `{"ok":true,"version":"2.5.44","db":"ok","uptime":54.2}`，
     但证书**不受信任**（自签/内部 CA），`nginx` 回源，HSTS 已开
     → 实际线上是"IP + 自签证书 + HTTPS"，文档写的是"IP:8080 + 明文 HTTP"。**任何按文档配置的客户端或监控都会判定失败。**
     另：探测时（01:33:48）`uptime` 仅 54 秒，而维护者本机正在改 `deploy/upgrade.sh`（01:38 保存，内容正是"v2.5.44 升级实战首撞：down 后 cwd 停在旧目录，裸 create 重建了旧容器"）—— 判定为**升级重启而非崩溃循环**；但也说明 `upgrade.sh` 的路径/项目名锚定修复尚未提交，且升级后 8080 端口映射消失（拓扑变化未被任何文档记录）。

   **状态（2026-09-30）：已闭合。** 真实拓扑由同日「§0.2-① 已被证伪」一节纠正，地址统一为 `https://napi.iniess.cn`；
   状态页改由拨测生成（`status-probe.mjs` 写 `docs/status.md` 的生成区），`bump-version.mjs` 不再刷绿。
   残留：明文收口未完成（见 §0.2-2 与文末仍待办第 2 条）。

2. **没有外部拨测，"服务状态"是自动化的假绿**
   `docs/status.md` 的"最近人工核对"日期由 `scripts/bump-version.mjs` 随发版自动归一 ——
   也就是说：**发版这个动作本身会把状态页刷成 🟢**，而不是探测结果。`operations-runbook.md §3.2`
   自己也把"外部拨测"列为待建设。单用户自托管产品，"你的服务器还在不在"是用户第一个问题。

   **状态（2026-10-02 收口）：告警链路已修好并实测通过。** 外部拨测 = GitHub Actions 每 6 小时排期，
   失败开 issue、恢复自动关闭；服务器侧 Prometheus + Alertmanager 确实在跑。
   **更正（2026-10-02 实测，推翻上一版这句话）**：原文「+ ntfy 已接线」不成立。Alertmanager → 手机
   那一跳是断的——线上 `/opt/dustnote-server-v2.5.45/.../bridge.mjs` 是 P0-2 修复**前**的旧版（2590 B，
   仓库 HEAD 5171 B），且 `NTFY_SERVER=http://ntfy:5000` 指向一个从未存在的容器。「零送达即 502 让 AM
   重试」是仓库代码的性质，不是线上事实。证据与修法见文末「服务器入口到位」落。
   **已归档**：全量演练实跑（拔主栈 → 2m10s 内送达双目标 → 恢复 → resolved），
   实测数字见文末「R1 与告警链路一起收口」落。手机订阅仍待你做（把 topic 给你即可）。

3. **图片/附件是"单机私产"，跨设备/跨端/导出/分享全部丢图**（代码级证据）
   `web/src/lib/image-store.ts` 把正文里的 base64 抽到 **IndexedDB**，正文只留 `![alt](dustnote-img://id)`。
   全仓只有 `web/src/components/Editor.tsx` 在渲染前还原引用 ——
   - 联机同步到另一台设备：服务端只有密文正文，引用指向的字节对端不存在 → 空图
   - 导出 ZIP / JSON / HTML / PDF、在线分享页（`shares.title/content`）：引用原样带出去 → 空图
   - `mobile` 完全没有该协议实现；`miniprogram/src/lib/markdown.tsx:92` 明确"仅渲染 http(s) 外链，
     `dustnote-img://` 等本地引用不渲染" → 空图
     → 用户视角的"端到端加密笔记"，**带图片的笔记实际上是不可靠的**。这是当前最大的产品级数据风险，
     比审计台账里任何一条都严重。

   **状态（2026-10-02 更正）：跨设备问题未动，但四步止血已落地并有 e2e 证据。**
   ①联机插入当场提示、②导出/备份还原成 data URL、④渲染出口换占位图——三项都在代码里，
   此前缺的是自动化证据（①② 触达 IndexedDB，纯函数单测覆盖不到），现已补 `e2e/image-triage.spec.ts`。
   剩下的仍是那句判断：**带图片的笔记跨设备不可靠**，根治要附件系统 v1（§4.1）。

4. **三个客户端包零单测**：`desktop` / `mobile` / `miniprogram` 的 `test` 脚本是 `echo [skip]`（审计 TEST-001 已知），
   `miniprogram` 连 `lint` 脚本都没有；e2e 只有 3 个 spec（`e2e/core-flow`、`folders-unfiled`、`online-flow`）。
   四端行为一致性目前靠"人肉核对 + 审计台账"维持 —— 这正是 `client-core` 想消灭的东西，但下沉还没做完
   （`ARCH-R01` 剩余、`i18n 三端合并`、`getDeviceId` 之外还有 crypto-polyfill / storage 适配层）。

   **状态（2026-09-30）：已闭合。** 三个包都有真测试：desktop 29 / mobile 31 / miniprogram 42；
   `echo [skip]` 占位全部清除（含 `miniprogram` 的 `lint` 脚本），见「同日第十落」TEST-004。

5. **更新链路的信任根仍是服务器自己**：minisign 验签未落地（`security-model.md §2.5` 明说白名单防的是误配置，
   不是服务器被攻破）；Windows 无代码签名、macOS 未签名（README 让用户"右键打开"）。
   自动更新是 E2EE 产品最脆弱的供应链环节，目前是二流水准。

   **状态（2026-09-30）：未动。** minisign 验签与代码签名仍是 R1 的硬骨头；
   期间 `pnpm audit` 的触发信号真响过两次（vite / vitest 新公示 advisory），
   一次是官网包 devDeps 引旧版（已对齐），一次是传递依赖（override 或登记豁免）。见 09-30 落。

6. **巴士因子 = 1**：`status.md` 自述"单维护者项目，暂无对外 SLA 承诺"。
   所有决策、发布、运维、答疑集中于一人，任何长期路线都必须回答"这件事能不能自动化/能不能交给别人"。

   **状态（2026-09-30）：未变，但可交接性提高了。** 现在一个新人能照着
   `CONTRIBUTING.md` 的门禁总表 + 各目录 README + `docs/adr/` 独立跑完 `pnpm verify` 并知道每条规矩为什么在；
   但「谁能批准发版、谁能碰服务器、谁能处理安全报告」仍然只有一个人。

## 1. 三条主轴

| 主轴                   | 内容                                                   | 时间窗    | 为什么排在这个位置                                       |

而不是按用户请求的到达顺序排。

## 4. R2 · 结构债与回归保护（`v2.7.0`，3–6 个月）

目标：**把"四端一致"从人肉纪律变成机器保证；把附件这个数据模型缺口正式补上。**

### 4.1 附件系统 v1（本阶段最大功能项，也是 P0-3 的最终解）

notes ──(1:N)── attachments(id, note_id, dek_wrapped_blob_meta, size, mime, sha256, created_at)

## 5. R3 · 能力扩展（`v3.0.0`，6–12 个月，按依赖排序）

> 顺序不是"哪个更酷"，而是"哪个是另一个的前置"。

1. **数据可移植性优先**：与 Joplin / Obsidian / 纯 Markdown 目录的双向导入导出（含图片附件、文件夹、标签）。
   _理由_：E2EE 自托管产品最大的反对意见是"锁死"，先拆掉这个反对意见，后面所有功能才有人愿意试。
2. **客户端全文检索增强**：同义词/拼音/语义向量索引（仍在本地），并解决"多设备索引重建"策略。
   _红线_：**绝不做服务端明文检索**（会直接毁掉零明文承诺，见 §7）。
3. **双向链接与关系图**：`web/src/lib/wikilinks.ts` 已有雏形 → 反链面板 + 图谱视图（桌面优先）。
4. **协同（分两步）**：
   - 4a 多人**只读**分享 + 评论（服务端仍只见密文，密钥通过一次性分享链接下发）
   - 4b **CRDT 协同编辑**（Yjs over WebSocket，服务端只存密文 update log + 快照）
     _前置 ADR_：E2EE 下的协作者密钥协商 —— 每加一人需对其 re-wrap，**主密码泄露半径会扩大到协作者集合**，
     这是产品定位级别的决定，必须先写 ADR 再写代码。
5. **家庭 / 团队版**：多用户 + 组密钥 + 管理员与审计（同 4b 的密钥协商），也是 §6 商业化的载体。
6. **iOS 正式发布**：RN 代码已就绪，阻塞项是 Mac 硬件 + Apple 开发者账号；顺带解决 macOS 桌面构建实测（README 目前 `continue-on-error`）。
7. **AI 能力（最后做，且规则先行）**：写作润色、自动标签、基于本地索引的问答。
   _红线_：默认只在本地/自建推理；任何"明文离开设备"的路径必须显式确认、可在设置里永久关闭、
   并同步写进 `docs/security-model.md` 的取舍表。**不做静默上云摘要。**
8. **开放能力**：REST API（读为主）+ PAT 令牌 → 只读 Webhook → 沙箱插件（自定义块/主题）。
   _顺序理由_：API 会立刻产生"用户依赖"，必须在 HTTPS 与验签稳定后（R1）才暴露。

**（同日再续）#13 的复核结果，以及读 #6 时撞出的真 bug**

合并 `c074fbb` 后 main 的分析：open **9 → 7**。#7、#8 两条 `insecure-randomness` 被
「两个源两个出口」的重构关掉了——证明那不只是我说的大道理，确实改变了污点图。
#6 仍在（`auth-slice.ts` 里被包裹主密钥那一行）。

#6 剩下的那条流本身是**设计上允许**的：唯一性源只可能被 `randomUniqueBytes()` 取到，
而它唯一的调用点是 AES-GCM 的 IV；IV 会随密文信封流进各处，所以工具还能看见它，但
「保密」从来不是 IV 的要求。真要 dismiss 的口径是「这条流的语义是 nonce 传播，不是密钥
泄露」——写清楚，别写成「工具误报」。

但顺着它读 `localFallbackBytes` 的实现，读到一处**实打实的缺陷**：兜底字节的前 12 位是
「8B 毫秒时间戳 + 4B 递增计数器」，`Math.random` 只补第 12 位之后——也就是说 12 字节的
GCM IV **完全由时间戳+计数器决定**，而计数器原先每次从 0 开始。于是「进程重启 + 时钟回拨
到同一毫秒」会产出逐字节相同的 IV（用现网算法实测：两次独立进程同毫秒都得到
`123,192,44,200,153,1,0,0,1,0,0,0`）。同一密钥重用 IV 对 AES-GCM 是灾难级的。

修法：计数器改从随机起点开始（`fallbackCounter = Math.floor(Math.random() * 0xffffffff)`）。
这里用 `Math.random` 是正当的——它只负责「不重复」不负责保密，2^32 的起点空间把「同毫秒

1. **TS 模板插值不是环境变量**。第一版把 `n=${NEW_N}`、`${DIGITS}`、`${PREFIX}` 全报成
   「代码读了但清单没登记」——31 条里 10 条是这种。修法：按文件类型分流（`kindOf`），
   `${VAR}` 插值语义只对 yml / Dockerfile / Caddyfile / conf 生效。
2. **yml 整行注释里的插值不是读取**。`compose.monitoring.yml` 的说明行「主栈发布在
   `${PORT:-8080}」被当成真实读取，报出 `PORT`与`METRICS_TOKEN`两条假缺口。
修法：只剥整行注释（行首空白 +`#`）。**行尾注释不剥**——那需要真 YAML 解析器；
这条边界写进了测试断言（`SKIP` 仍在结果里），因为「多认一个名字只会让守卫更严，不会漏」。
3. **shell 脚本不能与 compose 共用一套读法**。第一版把 `.sh` 也纳入，`${MON_DIR}`、`${AFTER}` 这类
   局部变量全被报成环境变量，噪音从 12 涨到 64。修法：不扫 shell（不做赋值流分析就分不清），
   边界写在文件头：`deploy.sh` / `alert-drill.sh` 的入参由它们自己的 `--help` 与文档负责。

   同一条守卫还自我踩了一次：它自己的注释里写了 `process.env['FOO']`，于是扫到自己，
   报出一条「FOO 没登记」。**守卫扫到自己不算错，报出自己写的例子才算错**——改掉了例子。

#### 做了什么

1. **状态页的自动更新从承诺变成实现**（`.github/workflows/nightly-status.yml`）
   原状：作业只把 `probe.json` 传成 artifact，既不传 `--update`、也没有提交，
   而页面写着「手改无效：下一次拨测会覆盖」。实测 09-27 → 10-01 期间页面停着 4 天前的数据，
   中间 10 多次拨测全部成功却一次没落笔。现在：
   - 探针带 `--update` 跑，生成区随作业产物传出；
   - 新增 `publish` job 把它提交回 `main`，提交信息带 `[skip ci]` 切断自我触发；
   - `publish` 失败单独开「状态页发布失败」的 issue，与「线上挂了」分开——
     前者是报告板故障，按后者去查会查错方向；
   - 探针侧补一条：`--update` 时若生成区标记丢失，必须 exit 1。
     旧实现是「`next === md` 就算没写」，而标记丢了时 replace 静默不命中、探针照样 exit 0，
     于是页面永远停在旧数据上而没人知道。判据改成「标记在不在」，与「内容变没变」分开。
   - 顺带修掉一个把上面这条抹平的写法：文件末尾 `process.exitCode = allOk ? 0 : 1` 是无条件赋值，
     会把刚置成的 1 改回 0。新测试正是这样抓到它的——**先写测试，实现里的坑自己浮出来**。

2. **实时同步终于有了自动化证据**（新增 `e2e/realtime-sync.spec.ts`）
   此前全仓 49 个测试文件里只有 1 处顺带提到 ws，而 README 与官网都写着「1 秒内同步到所有在线设备」；
   客户端也没有轮询兜底（`sync-ws.ts` 里 `setInterval` 0 处、无 visibilitychange/focus 重拉），
   所以这件事只能由 WS 兑现，而 WS 静默断掉时没有任何测试会红。
   用例做两端：A 写入 → B **不刷新、不切视图**看到；再反向验一次，排除单向生效。
   本机实测端到端 0.9–2.0s（含 1.5s 自动保存防抖 + 0.3s 广播防抖），断言上限放 5s——
   **这条测的是「会不会永远收不到」，不是精确延迟**；延迟每次 console.log，攒 run 出 P95。

3. 写这条用例当场撞出**开发环境缺 WS 传输**：`web/vite.config.ts` 的 `/api` 代理没开
   `ws: true`，而 vite 默认**不代理 WebSocket 升级**。生产由 nginx 带 Upgrade 头转发所以线上是好的，
   但开发与 e2e 里实时同步链路根本连不上，客户端只会静默退避重连——表现像「功能坏了」，
   实际是「环境缺了传输」。已补 `ws: true` 并写明来历。

4. 同一条用例又撞出**应用内导航丢未保存内容**（真数据丢失，非测试瑕疵）：
   打字后 800ms 防抖窗口内切视图（概览/全部笔记/收藏/文件夹），`Editor.tsx` 的自动保存清理
   只在「笔记 id 变了」时补存，而切视图时 id 没变、组件整个卸载，`clearTimeout` 之后无人补存。
   实测：POST 建了空笔记，之后**一个 PATCH 都没有**，内容永久丢失。
   `beforeunload` 那道防线只管关页面，管不了应用内导航。
   修复：加一个空依赖的卸载 effect，用 ref 读最新草稿，卸载时若有脏草稿就补存
   （回收站只读不补存）。不能把补存放进原 effect 的清理里——它每次按键都重跑，
   无条件补存等于每敲一个字发一次 PATCH。
   回归用例：`"打字后立刻切视图，未保存内容不许丢"`，并额外 reload 一次——
   只有真的进了服务端才可能活过 reload。

5. **图片止血补上集成面证据**（新增 `e2e/image-triage.spec.ts`，2 条）
   ①联机插入 → 当场出现「不会同步到其他设备」提示，且正文留下 `dustnote-img://` 引用；
   ②切预览 → 引用真的从 IndexedDB 还原成 `data:image/png;base64,` 带 MIME 的 data URL
   （导出路径调的是同一个 `restoreNoteImages`，所以「导出含图」是从共享机制推出的，
   不是逐个下载验过——这条边界写在文件头）。
   ④引用无本体 → 渲染出口换成 SVG 占位，且预览里不许出现裸协议串文本。
   写这条时也误报过一次：拿 `locator('img').first()` 断言占位图，结果命中的是界面上
   别的图标 img。定位必须按 src 前缀收窄——**误报的测试比没有测试更糟，它会教人忽略红**。
