# 0005 · action 钉版，但必须校验可解析性

状态：生效（2026-09-29）

## 背景

供应链上把 action 钉到 commit 是正解；但**钉一个不存在的 commit 比不钉更糟**：它不会给出
「使用了可变 tag」的警告，而是让 job 在 Set up job 阶段直接失败，而失败通知如果同在这个 job
里就彻底无声（见 0004）。本仓库的拨测 workflow 就是这么静默了两天。

## 决策

- 允许 `@v5` 这类可变 tag 存在（要不要全钉是人的选择，不默认拦），但**存在性必须验**；
- 钉 SHA 的必须能解析，且注释里写了版本号的，SHA 必须真是那个 tag 指向的提交（annotated tag
  要二次解引用）；
- 「问不到」（限流 / 5xx）与「不存在」分开处理：前者单独报数不判红。把 CI 的红绿绑在第三方
  API 的可用性上，只会训练人去忽略这条门禁。
- 守卫跑在每次 push 都执行的 lint job 里，且 `GITHUB_TOKEN` 显式注入——不依赖被检查者自己，
  也不依赖 runner 共享出口 IP 的运气。

## 后果

- 第一版实现就把自己跑挂了：没有按 (repo, ref) 去重，92 处引用逐个查，未认证额度当场烧穿。
  教训写进代码注释：**给监控加监控之前，先算它自己会不会成为新的静默点**。
- 多一条 CI 依赖 GitHub API；用去重 + unknown 三态把不稳定性挡在判定之外。
- 现状：仓库 95 处 uses，3 处钉 SHA（全部可解析且与注释一致），15 个不同可变引用全部存在。

证据：`scripts/check-action-pins.mjs` 与其 8 例测试（含变异验证：退回假 SHA 即 exit 1）。
