# 0001 · 单机与联机共用同一套数据模型

状态：生效（v2.0.0 起）

## 背景

最容易写出来的版本是两套存储两套代码：本地一套、同步一套。但用户会在一台设备上两种模式间
来回切，任何差异都会变成「数据丢了」的观感。

## 决策

`mode-store` 只决定**仓库实现**走本地还是远端；上层数据结构、加密信封、冲突语义完全相同。
切换模式不改变已有数据形态，联机时按同一份信封逐条上传。

## 后果

- 好处：一份 client-core 服务五端；测试只需覆盖一种数据形状。
- 代价：本地实现必须容忍「以后会被服务端乐观锁裁决」，所以版本号从第一版就存在，而不是等同步时再加。
- 代价：文档必须解释清楚「切模式不是迁移」，否则用户会以为选了就要永远留在那个模式。

证据：`client-core/src/mode-store.ts`、`client-core/src/remote-repository.ts`、
[用户手册 §12 模式切换](../user-guide.md)`（同一份数据两种落点）`。
