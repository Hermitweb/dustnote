# DustNote v2.0.0 单机/联机双模式架构 + 文档更新 + 补全开发

## Context

DustNote 当前已交付 v0.1.0\~v1.5 全栈跨端能力（Web/桌面/Android/小程序），但架构上**所有端都硬依赖服务端**（如 [mobile/src/api.ts:38](file:///e:/workspace/dustnote/mobile/src/api.ts#L38) 硬编码 `localhost:3210`），用户在没有服务器的情况下无法使用任何客户端。同时 [mobile/src/screens/SettingsScreen.tsx:55-64](file:///e:/workspace/dustnote/mobile/src/screens/SettingsScreen.tsx#L55) 的导入/导出、分享管理仍是 Alert 占位，文档也未反映当前进度。

本次调整为 **v2.0.0 重大架构变更**：引入单机/联机双模式，让各端可在无服务器情况下独立运行，连接服务器后解锁跨设备同步、在线分享等高级功能。同时补全所有未开发功能、更新全部文档、规范 GitHub Release 资产结构，做到「不留未开发需求」。

## 一、架构设计

### 1.1 核心抽象：DataRepository 接口

在 [shared/src/repository.ts](file:///e:/workspace/dustnote/shared/src/repository.ts)（**新增**）定义统一接口契约，让客户端 store/state 不再直接持有 ApiClient，而是持有 DataRepository。各端启动时根据模式注入不同实现：

```
shared/src/repository.ts           ← 接口契约（仅类型）
shared/src/local-auth.ts           ← 单机模式鉴权工具
web/src/lib/local-repo.ts          ← IndexedDB 完整 CRUD
web/src/lib/remote-repo.ts         ← 封装现有 ApiClient
mobile/src/lib/local-repo.ts       ← MMKV 完整 CRUD
mobile/src/lib/remote-repo.ts      ← 封装 api 调用
miniprogram/src/lib/local-repo.ts  ← Taro.setStorage 完整 CRUD
miniprogram/src/lib/remote-repo.ts ← 封装 getApi() 调用
```

接口对齐 [web/src/lib/store.ts](file:///e:/workspace/dustnote/web/src/lib/store.ts) 现有 action 签名：`loadAll/createNote/updateNote/moveNote/deleteNote/permanentDeleteNote/emptyTrash/restoreNote/createFolder/deleteFolder/listTags/createTag/deleteTag/getPreferences/setPreferences/exportBackup/importBackup`。**不含鉴权方法**（setup/unlock/lock 由 mode-store + auth-store 处理）。

### 1.2 模式判定与切换

每端新增 mode-store（独立于 auth-store）：

* `web/src/lib/mode-store.ts`

* `mobile/src/state/mode.ts`

* `miniprogram/src/state/mode.ts`

字段：`mode: 'standalone' | 'online'`、`serverUrl: string | null`、`initialized: boolean`、actions: `chooseStandalone()` / `chooseOnline(serverUrl)` / `switchMode(mode, serverUrl?)`

持久化：Web=localStorage、Mobile=MMKV、小程序=Taro.setStorageSync。

### 1.3 首次启动选择 UI

* `web/src/components/ModeSelectDialog.tsx`

* `mobile/src/screens/ModeSelectScreen.tsx`

### 1.4 能力矩阵

| 能力               | 单机模式                                       | 联机模式                       |
| ---------------- | ------------------------------------------ | -------------------------- |
| 主密码 setup/unlock | 本地 Argon2id + 比对（无 JWT）                    | 调 /auth/setup、/auth/unlock |
| 笔记/文件夹/标签 CRUD   | local-repo（IndexedDB/MMKV/Taro.setStorage） | remote-repo（API + 离线队列）    |
| 偏好设置             | 仅本地                                        | API + 本地双写                 |
| 分享               | **仅导出文件**（txt/md/html/pdf）                 | 在线分享链接 + 文件导出              |
| 设备管理             | 不支持（UI 隐藏）                                 | 支持                         |
| 跨设备同步            | 不支持                                        | WebSocket + 离线队列           |
| 自动更新             | GitHub Release（Velopack）                   | 同上 + /update-manifest      |

### 1.5 单机鉴权（shared/src/local-auth.ts 新增）

复用 [shared/src/crypto.ts](file:///e:/workspace/dustnote/shared/src/crypto.ts) 的 Argon2id + AES-256-GCM：

* `setupLocalAuth(password)` → 派生 masterKey + 生成 recoveryCode + wrapMasterKey + passwordHash

* `unlockLocalAuth(password, blob)` → 比对 passwordHash（constantTimeEqual）

* `recoverLocalAuth(recoveryCode, newPassword, blob)` → recoveryKey 解封 → 重新派生

本地存储字段：`local_password_hash` / `local_master_salt` / `local_client_master_salt` / `local_wrapped_master_key` / `local_recovery_hash` / `local_recovery_salt`。客户端锁定（6 次失败锁 15 分钟）也本地实现。

### 1.6 数据迁移（standalone ↔ online）

显式操作（用户点「迁移数据」按钮触发，不自动）：

* **standalone → online**：检查 /auth/status → /auth/setup → 遍历 local-repo 调 remote-repo.createXxx 批量上传 → 清空 local-repo 业务数据

* **online → standalone**：调 /export/backup 拉全量密文 → 写入 local-repo → 切换 store

新增 `web/src/lib/data-migration.ts` 实现 `migrateStandaloneToOnline()` 和 `migrateOnlineToStandalone()`，原子化 + 失败回滚。

### 1.7 桌面端复用

[desktop/src/App.tsx](file:///e:/workspace/dustnote/desktop/src/App.tsx) 已 `import WebApp from '../../web/src/App'`，web 端所有改造自动复用。仅需修改 [desktop/src/lib/updater.ts](file:///e:/workspace/dustnote/desktop/src/lib/updater.ts) 加模式分支：单机走 Velopack GitHub Releases，联机额外查 /update-manifest。

## 五、风险与应对

| 风险                | 应对                                                   |
| ----------------- | ---------------------------------------------------- |

## 七、关键设计决策

1. **Repository 接口放 shared 层**：所有端共享类型契约，避免实现漂移
2. **mode-store 独立于 auth-store**：模式切换不影响鉴权状态
3. **保留现有 offline-first**：联机模式下 IndexedDB 缓存 + 离线队列不变
4. **单机模式不用离线队列**：所有操作直接写本地
5. **数据迁移显式触发**：用户点按钮才迁移，避免意外覆盖
6. **Velopack 资产命名只改用户入口**：内部文件保留原名
7. **mobile 用 MMKV 而非 SQLite**：遵循用户决策；预留接口可切换
8. **小程序单机作轻量试用**：受 10MB 限制，文档明确
