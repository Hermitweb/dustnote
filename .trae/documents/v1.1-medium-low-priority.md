## 第二批：核心功能（离线优先 + 移动端/小程序补页）

### 4. Web 端 Offline-first（Item 6）

**文件：`web/src/lib/db.ts`（新建）+ `web/src/lib/offline-queue.ts`（新建）+ `web/src/lib/store.ts` + `web/src/lib/sync-ws.ts` + `web/src/components/Sidebar.tsx`**

设计原则：仅 Web 端，务实不过度设计。不做 Service Worker/PWA，不做 CRDT。

- `web/package.json` 新增 `idb-keyval: ^6.2.1`
- **新建 `db.ts`**（IndexedDB 封装）：
  - `cacheNotes(notes, plain)` / `loadCachedNotes()` — 缓存密文+明文（Map 需转 `[k,v][]`）
  - `cacheFolders(folders)` / `loadCachedFolders()`
  - `cacheTags(tags)` / `loadCachedTags()`
  - `clearCache()` — 注销时调用
- **新建 `offline-queue.ts`**（同步队列）：
  - `QueuedOp { id, method, path, body?, createdAt, noteId?, retries }`
  - `enqueue(op)` / `dequeue()` / `peekAll()` / `clear()`
  - 持久化到 IndexedDB（`dustnote:offline-queue`），刷新不丢
- **修改 `store.ts`**：
  - StoreState 增加 `isOnline: boolean`、`pendingCount: number`、`setOnline()`、`flushQueue()`
  - `loadAll()` 先从 IndexedDB 加载缓存填充 store（UI 立即可见），同时发网络请求
  - 每个 mutation action（createNote/updateNote/deleteNote/moveNote 等）：立即乐观更新 store；网络失败时 enqueue 而非 throw
  - `flushQueue()`：逐条重放，409 冲突时取 `current` 更新本地、丢弃该 op、toast 提示
- **修改 `sync-ws.ts`**：WebSocket `open` 回调中先 `flushQueue()` 再 `loadAll()`
- **新建 `web/src/lib/online-listener.ts`**：注册 `online`/`offline` 事件 → setOnline + flushQueue
- **修改 `Sidebar.tsx`**：顶栏增加离线徽章 `⚠ 离线 · N 条待同步`
- **新建 `offline-queue.test.ts`**：enqueue 顺序、持久化恢复、flushQueue 清空、409 丢弃

## 验证方式

1. **PDF 导出**：在编辑器导出 .pdf，下载文件用 PDF reader 打开，中文可读
2. **CI weapp**：推送后 CI 同时跑 H5 + weapp 两份构建，weapp 失败能阻断合并
3. **docker-compose**：`docker compose up -d --build` 一键启动，`curl localhost:3210/api/v1/health` 返回 notesCount
4. **离线优先**：断网 → 创建/编辑笔记 → UI 立即响应 → 联网 → 队列自动重放 → 数据一致；顶栏显示离线状态
5. **移动端页面**：新建/重命名/删除文件夹、标签；查看回收站、恢复、永久删除
6. **小程序页面**：设置页有文件夹/标签/回收站入口，新页面在 H5 + weapp 构建下正常渲染
7. **跨平台构建**：Release tag 推送后 CI 产出 Windows/macOS/Linux 三平台安装包
8. **i18n**：切换到 en 后无中文残留（除注释）；CI 检测出未定义的 i18n key
